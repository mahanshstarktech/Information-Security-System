Cryptographic Hash Functions — Basics

85%

What is a Hash Function?

A cryptographic hash function is a mathematical function that takes an input of arbitrary length and produces a fixed-size output called the hash value, message digest, or fingerprint. The output size is fixed regardless of input size.

A hash function is like a fingerprint machine. No matter how long or short a document is, it produces a fixed-length unique fingerprint. Change even one letter in the document — the fingerprint changes completely. But you cannot reverse-engineer the original document from just the fingerprint.
Hash Function — Mathematical Notation
h = H(M)
M = message of any length | h = hash value of fixed length (e.g., 256, 512 bits)
Examples: SHA-256 → 256-bit output | SHA-512 → 512-bit output | MD5 → 128-bit (broken)

Simple Hash Functions — How They Work

The simplest hash functions use bit-by-bit XOR of each data block:

Simple Hash using XOR (Longitudinal Redundancy Check)
hᵢ = bᵢ₁ XOR bᵢ₂ XOR bᵢ₃ XOR ... XOR bᵢₘ
bᵢⱼ = i-th bit of j-th block | The hash is XOR of corresponding bits across all blocks
Limitation: Easy to break — attacker can modify two bits in same position and cancel the XOR change

Rotated XOR (Better Simple Hash)

C̃ᵢ = C̃ᵢ₋₁ ROL 1 ⊕ Dᵢ
Each round: Rotate current hash value left by 1 bit, then XOR with next block. Still not cryptographically secure — real hash functions (SHA) use complex mixing operations.
🔗
Connection — Unit 3 (Block Ciphers) → Unit 5 (Hash Functions)

Hash functions and block ciphers are deeply related! CBC-MAC (Unit 5) literally uses AES (Unit 3) in CBC mode to generate a MAC. SHA uses similar bitwise operations (AND, OR, XOR, NOT, shifts) as DES. If you understood AES S-boxes and DES rounds, you already have the mental model for hash compression functions.

🧠
Memory Trick — "VEF-OWC-P" for 7 Requirements

Variable input, Efficiency, Fixed output, One-way, Weak collision resistance, Collision resistance (strong), Pseudo-randomness. Or: "Very Efficient Functions Obstruct Wrong Cryptanalysis Perfectly."

Hash Function Security — Birthday Attack

Birthday Attack Complexity
Preimage attack: O(2ⁿ) computations
Collision attack: O(2^(n/2)) computations ← much easier!
Why MD5 (128-bit) is broken: collision needs 2^64 ops — feasible today
Why SHA-256 is secure: collision needs 2^128 ops — computationally infeasible
The birthday paradox: in a room of 23 people, 50% chance two share a birthday. Similarly, with only 2^(n/2) hash computations, you have 50% chance of a collision — much less than the 2^n you might expect. That's why longer hashes are needed.

Applications of Hash Functions

  • Message Authentication: Hash(message) sent with message — receiver recomputes and compares
  • Password Storage: Store hash(password) — if DB stolen, passwords remain safe
  • Digital Signatures: Sign H(M) instead of M — much faster (hash is small, M can be huge)
  • Intrusion Detection: Hash all system files — any change = different hash = detected
  • Blockchain: Each block contains hash of previous block — tamper-evident chain

Q. What is cryptographic hash function? Write its any two properties.
2024 Part A Q7 · 2023-Jul Part A Q7 · 2025 Part A Q7 · 2 marks ⭐⭐⭐Hash Function🔮 CERTAIN 2026
A cryptographic hash function H takes an input message M of arbitrary length and produces a fixed-size output h = H(M) called the hash value or message digest.

Two key properties:
1. One-way (Preimage Resistance): Given h, it is computationally infeasible to find M such that H(M) = h. Cannot reverse-engineer the original from the hash.
2. Collision Resistance: Computationally infeasible to find two different inputs M and M' such that H(M) = H(M').

Examples: SHA-256 (256-bit output), SHA-512 (512-bit output), MD5 (128-bit — now broken).
Q. Explain the security requirements for cryptographic hash functions.
2024 Part B Q5 · 4 marks ⭐⭐Hash Security
Three Critical Security Requirements:

1. Preimage Resistance (One-way): Given h, computationally infeasible to find M s.t. H(M)=h. Complexity O(2ⁿ). Ensures stored passwords cannot be reversed.

2. Second Preimage Resistance (Weak Collision): Given M, infeasible to find M'≠M with H(M)=H(M'). Complexity O(2ⁿ). Prevents forging a fraudulent document with same hash.

3. Strong Collision Resistance: Infeasible to find ANY (M,M') pair with M≠M' and H(M)=H(M'). Complexity O(2^(n/2)) due to birthday paradox — hardest to achieve! Required for digital signatures.

Additional: Pseudo-randomness — output passes statistical tests; small input change → completely different output (avalanche in hashing).

Hash Functions Based on Cipher Block Chaining

70%

Using Block Ciphers to Build Hash Functions

Block ciphers like DES and AES can be used to construct hash functions. The Davies-Meyer Construction is the most common approach.

Using a block cipher to make a hash is like using a padlock to make a fingerprint machine. You feed each piece of the message through the lock, where the output of one lock-operation feeds into the next. The final output is your fingerprint.
Davies-Meyer Construction
Hᵢ = Eₘᵢ(Hᵢ₋₁) ⊕ Hᵢ₋₁
E = block cipher (e.g., AES), mᵢ = i-th message block (used as KEY), Hᵢ₋₁ = previous hash (used as plaintext)
The ⊕ Hᵢ₋₁ feedforward is crucial — without it, the construction would be invertible
H₀ = IV (Initialization Vector), Hfinal = hash of message M
🔗
Connection to CMAC (Next Section!)

The CBC-based hash is the foundation of CMAC. In CMAC, we apply AES-CBC and use the last block output as the MAC. Hash-via-CBC = integrity only; CMAC uses a secret key to add authentication. Same CBC chaining — different security goal.

SHA-512 Algorithm — Step by Step ⭐⭐⭐

1
Append Padding Bits: Pad message M so length ≡ 896 (mod 1024). Padding = '1' bit followed by '0' bits. Always pad, even if already correct length.
2
Append Length: Append 128-bit representation of original message length. Total padded message is now a multiple of 1024 bits.
3
Initialize Hash Buffer: Set 8 initial hash values H₀–H₇ (512 bits total). These are the first 64 bits of the fractional parts of the square roots of the first 8 prime numbers (2,3,5,7,11,13,17,19).
4
Process Message in 1024-bit Blocks: For each 1024-bit block Mⁱ, perform 80 rounds of the compression function.
5
80 Rounds of Compression: Each round uses a 64-bit word Wₜ (from message schedule) and round constant Kₜ (from cube roots of first 80 primes). Apply six Boolean functions (Ch, Maj, Σ₀, Σ₁, σ₀, σ₁) to mix the 8 working variables a-h.
6
Output: After all blocks, final 512-bit hash = concatenation of H₀ through H₇.
SHA-512 Six Boolean Functions (Write in exams!)
Ch(e,f,g) = (e AND f) XOR (NOT e AND g)
Maj(a,b,c) = (a AND b) XOR (a AND c) XOR (b AND c)
Σ₀(a) = ROTR²⁸(a) XOR ROTR³⁴(a) XOR ROTR³⁹(a)
Σ₁(e) = ROTR¹⁴(e) XOR ROTR¹⁸(e) XOR ROTR⁴¹(e)
σ₀(x) = ROTR¹(x) XOR ROTR⁸(x) XOR SHR⁷(x)
σ₁(x) = ROTR¹⁹(x) XOR ROTR⁶¹(x) XOR SHR⁶(x)
ROTR = Rotate Right, SHR = Shift Right | Upper Σ: compression | Lower σ: message schedule
SHA-512 One Round — Update Equations
T₁ = h + Σ₁(e) + Ch(e,f,g) + Kₜ + Wₜ
T₂ = Σ₀(a) + Maj(a,b,c)
h←g, g←f, f←e, e←d+T₁, d←c, c←b, b←a, a←T₁+T₂
8 working variables a,b,c,d,e,f,g,h each 64 bits | Kₜ = round constant | Wₜ = message schedule word
Fig 4.1 — SHA-512 One Round: T₁ path (Ch, Σ₁) and T₂ path (Maj, Σ₀) combine to update 8 working variables

Message Authentication Codes (MAC)

🔥 85%

What is a MAC?

A Message Authentication Code (MAC) is a short piece of information used to authenticate a message AND verify its integrity. Unlike a hash function (which uses no key), a MAC uses a shared secret key K between sender and receiver.

A hash is like a fingerprint — anyone can check it. A MAC is like a fingerprint + a wax seal that only you and your trusted friend can create and verify (because it needs a shared secret key). Even if an attacker sees the MAC tag, they cannot fake it without knowing the key.
MAC Function
MAC = C(K, M) or MAC_K(M)
K = shared secret key | M = message | Sender sends: (M, MAC)
Receiver computes MAC' = C(K, M). If MAC = MAC' → authentic and unmodified.
ServicePlain HashMACDigital Signature
Message Integrity✅ Yes✅ Yes✅ Yes
Authentication❌ No✅ Yes (shared key)✅ Yes (public key)
Non-repudiation❌ No❌ No (both parties have key)✅ Yes
Confidentiality❌ No❌ No❌ No

MAC Requirements

  • Computationally infeasible to forge: Without K, attacker cannot compute valid MAC even after seeing many (M, MAC) pairs
  • Consistency: Same M and K always produce same MAC (deterministic)
  • Uniform distribution: For random K, any MAC tag is equally likely — no bias
  • Equal dependence on all bits: Changing any single bit of M or K changes the MAC drastically (avalanche)
📝 RTU PYQs — MAC
Q. What are the requirements of Message Authentication Codes?
2025 Part A Q8 · 2 marks ⭐MAC🔮 HIGH confidence 2026
Requirements of MAC (Message Authentication Code):

1. Unforgeability: Without knowing the secret key K, an attacker cannot compute a valid MAC for any message — even after observing many valid (M, MAC) pairs.
2. Consistency: MAC is deterministic — same K and M always produce identical output.
3. Uniform distribution: For a random secret key, any tag value is equally likely. An attacker cannot predict the MAC without the key.
4. Avalanche effect: A change in any bit of M or K produces a drastically different MAC — equal dependence on all input bits.

What MAC provides: Message integrity + Authentication (but NOT confidentiality, NOT non-repudiation since both parties hold the same key).

HMAC — Hash-based MAC

82%

HMAC — Keyed Hash for Authentication

HMAC uses a cryptographic hash function combined with a secret key to produce a MAC. It was designed to fix the length-extension attack vulnerability in naive "prepend key" approaches.

Naive idea: MAC = Hash(key || message). Problem: SHA is vulnerable to length extension — an attacker who knows Hash(key || M) can compute Hash(key || M || extra_data) without the key! HMAC fixes this by applying the key twice: once inside, once outside the hash.
HMAC Formula ⭐⭐⭐
HMAC(K, M) = H[(K⁺ XOR opad) || H[(K⁺ XOR ipad) || M]]
K⁺ = key K padded with zeros to block size b
ipad = 0x36 repeated b/8 times (inner padding)
opad = 0x5C repeated b/8 times (outer padding)
|| = concatenation | Two hashes, two different key pads
Fig 6.1 — HMAC: Key applied twice (inner as ipad, outer as opad) prevents length extension attacks
⚡
HMAC Memory Trick — "Inner/Outer Double Wrap"

HMAC = "Hash wrapping Hash" with a key. Remember: ipad = 0x36 (inner), opad = 0x5C (outer). Two padding constants, two hashes, two different key pads. The key point for exams: write the formula H[(K⁺⊕opad) || H[(K⁺⊕ipad) || M]] — outer hash wraps inner hash.

CMAC — Cipher-based MAC

🔥 92% — 3 Consecutive Years!
🔮
2026 Prediction: CMAC appeared in Part B in 2023-Jul, 2024, and 2025 — three consecutive papers. Near-certain for Part B Q4 in 2026. Draw the CBC chain diagram with K1/K2 subkeys — this alone earns 2 of the 4 marks.

CMAC — What and Why?

CMAC (Cipher-Based MAC), also called One-key CBC-MAC, is a MAC algorithm based on AES or 3DES. It is NIST-standardized (FIPS PUB 800-38B).

Simple CBC-MAC = run message through AES in CBC mode and use last block as MAC. Problem: for variable-length messages, it can be forged. CMAC fixes this by generating two special subkeys K1 and K2 from the main key, and XOR-ing one of them with the final block before the last encryption. This kills the variable-length forgery attack.
CMAC Subkey Generation (K1 and K2)
L = E(K, 0^b) ← encrypt b-bit zero block with main key K
K1 = L << 1 (if MSB(L)=0) OR K1 = (L << 1) XOR Rb (if MSB(L)=1)
K2 = K1 << 1 (if MSB(K1)=0) OR K2 = (K1 << 1) XOR Rb (if MSB(K1)=1)
Rb = 0x00...87 for AES-128 (128-bit). If you forget Rb, write "Rb is a constant in GF(2^n)"
CMAC Computation Steps
1. Partition M into b-bit blocks: M₁ || M₂ || ... || Mₙ
2. If Mₙ is complete (full block): Mₙ* = K1 XOR Mₙ
3. If Mₙ is incomplete: Mₙ* = K2 XOR pad(Mₙ) [pad = append '1' then '0' bits]
4. X₀ = 0^b (all zeros IV)
5. For i=1 to n-1: Xᵢ = E(K, Xᵢ₋₁ XOR Mᵢ) ← standard CBC
6. T = MAC = MSBₜ(E(K, Xₙ₋₁ XOR Mₙ*))
Only the LAST block uses K1/K2 — all previous blocks use standard CBC. T is truncated to Tlen bits.
Fig 7.1 — CMAC: Standard CBC for all blocks except last; final block XOR'd with K1 (complete) or K2 (incomplete)
✅
CMAC Answer Validation — Check These Points

1. K1 and K2 derived from E(K, 0) — NOT from the message
2. K1 = complete last block; K2 = incomplete last block (needs padding)
3. Only the LAST block uses K1/K2 — all previous = standard CBC
4. Final output MSBₜ(E(K, Xₙ₋₁ XOR Mₙ*)) — MAC can be truncated
5. Rb = 0x...87 for AES-128; if you forget just write "Rb is a constant in GF(2^n)"

Digital Signature — Introduction

🔥 90%

What is a Digital Signature?

A digital signature is a cryptographic mechanism that allows the sender to sign a message with their private key, and anyone with the corresponding public key can verify the signature. It provides authentication, integrity, and non-repudiation simultaneously.

A handwritten signature on paper proves you wrote something — but can be forged. A digital signature is like a handwritten signature + a tamper-evident seal + a lie detector test, all in one. It proves: (1) YOU signed it (only you have your private key), (2) the document wasn't changed, (3) you can't later deny signing it.
Digital Signature — Key Concept
Signing: S = Sign(M, private_key) → send (M, S)
Verification: Verify(M, S, public_key) → TRUE or FALSE
In practice: Sign H(M) not M directly. Hash is small → fast. Full message M can be huge.
🔗
Connection — Unit 4 (Public Key) + Unit 5 (Hash) = Digital Signature

Digital signature = Public Key Cryptography (Unit 4) + Hash Functions (Unit 5) working together. You hash the message (Unit 5), then encrypt that hash with your private key (Unit 4 — RSA or ElGamal). To verify, receiver decrypts with your public key and compares with H(M). Understanding both units makes digital signatures crystal clear.

Properties of Digital Signature

  • Authentication: Verifies the identity of the sender — only holder of private key can create the signature
  • Integrity: Any alteration of message M invalidates the signature — because H(M) changes
  • Non-repudiation: Sender cannot later deny signing — only they had the private key
  • Unforgeable: Without the private key, no one can create a valid signature
  • Not reusable: Signature is bound to the specific message — cannot be moved to another document
  • Verifiable by anyone: Public key is public — anyone can verify the signature

Requirements of Digital Signature

  • Bit pattern that depends on the message being signed
  • Must use unique information of the sender to prevent forgery and denial
  • Relatively easy to produce and verify
  • Computationally infeasible to forge (new message for existing signature OR fraudulent signature for a given message)
  • Must be practical to store a copy of the signature

Digital Signature vs MAC — Key Difference

AspectMACDigital Signature
KeyShared secret key (symmetric)Public/private key pair (asymmetric)
Non-repudiation❌ No — both parties have key✅ Yes — only signer has private key

How Digital Signature Works — With Hash Function ⭐⭐⭐

1
Hash the Message: Sender computes h = H(M) using a hash function like SHA-256 or SHA-512. This produces a fixed-size digest of the message.
2
Sign the Hash: Sender encrypts the hash using their private key: S = E(private_key, h). This is the digital signature S.
3
Send Message + Signature: Sender transmits (M, S) to receiver. M is in plaintext (or separately encrypted for confidentiality).
4
Verify — Receiver Decrypts: Receiver decrypts signature using sender's public key: h' = D(public_key, S). This recovers the hash that the sender signed.
5
Verify — Receiver Hashes: Receiver independently computes H(M) from the received message.
6
Compare: If H(M) = h' → signature valid → message authentic and unmodified. If they differ → signature invalid → message was altered or wrong sender.

⚡
Exam Trick — Draw Signing AND Verifying Separately

The 2025 paper explicitly says "with the diagrams showing functions of signing and verifying." Draw them as two separate boxes (as above). Signing: M → H(M) → Encrypt(privateKey) → S. Verifying: S → Decrypt(publicKey) → h' AND M → H(M); compare h' with H(M). This two-path diagram structure earns full marks for the diagram component.

📝 RTU PYQs — Digital Signature Introduction
Q. What is Digital Signature? List the security services provided by digital signature. Explain its uses with the help of an example.
2023-Aug Part C Q3 · 15 marks ⭐⭐⭐Digital Signature
Digital Signature — Definition:
A digital signature is a cryptographic value computed from data and a private key such that verification with the corresponding public key proves the data's authenticity, integrity, and non-repudiation.

Security Services Provided:
1. Authentication: Proves the identity of the signer — only holder of private key can produce a valid signature.
2. Data Integrity: Any modification of M changes H(M), invalidating the signature.
3. Non-repudiation: Signer cannot later deny signing — their unique private key was used.
4. Unforgeable: Without private key, no one can create a valid signature for any message.

How It Works (RSA-based example):
Signing: Alice computes h = SHA-256(M), then S = h^d mod n (encrypts hash with private key d,n)
Verification: Bob computes h' = S^e mod n (decrypts with Alice's public key e,n) and h = SHA-256(M); if h' = h → valid.

Example — Digital contract signing:
Alice and Bob agree to a contract M. Alice signs: S = Sign(H(M), Alice_private_key). Alice sends (M, S) to Bob. Bob verifies: Decrypt(S, Alice_public_key) = H(M)? If yes, contract is authentic. If Alice later claims she didn't sign it, Bob produces (M, S) — Alice's private key created S, proving non-repudiation.

ElGamal Digital Signature Scheme

85%

ElGamal Signature — Introduction

The ElGamal signature scheme is based on the same mathematical hardness as the ElGamal encryption system (discrete logarithm problem). Unlike ElGamal encryption (Unit 4), the signature scheme uses the private key to sign and the public key to verify.

You've already seen ElGamal encryption (Unit 4) where the public key encrypts and private key decrypts. ElGamal signature flips this for authentication: private key creates the signature and public key verifies it. Same math, different direction, different security goal.
🔗
Connection — Unit 4 ElGamal Encryption vs Unit 5 ElGamal Signature

Both use the same keys: prime q, generator α, public key Y = α^XA mod q, private key XA. The difference: Encryption → use Y to scramble; Decryption → use XA to unscramble. Signature → use XA to sign; Verification → use Y to check. Same math (modular exponentiation), same Discrete Log hardness assumption.

ElGamal Signature — Key Generation

Key Generation (same as ElGamal encryption)
Choose a large prime q and a primitive root α of q
Choose private key XA where 1 < XA < q-1
Compute public key: YA = α^XA mod q
Public: (q, α, YA) | Private: XA

ElGamal Signature — Signing Algorithm ⭐⭐⭐

Signing — Given message M
Step 1: Choose a random k where gcd(k, q-1) = 1 (k must be kept secret!)
Step 2: Compute S1 = α^k mod q
Step 3: Compute S2 = k⁻¹ (M - XA × S1) mod (q-1)
k⁻¹ = modular inverse of k with respect to (q-1)
Signature = (S1, S2) | M here represents the hash value H(M) in practice

ElGamal Signature — Verification ⭐⭐⭐

Verification — Given (M, S1, S2) and public key (q, α, YA)
Compute V1 = α^M mod q
Compute V2 = (YA^S1 × S1^S2) mod q
If V1 = V2 → Signature is VALID
Mathematical basis: α^M ≡ α^(XA·S1 + k·S2) = (α^XA)^S1 × (α^k)^S2 = YA^S1 × S1^S2 (mod q)
Fig 9.1 — ElGamal Signature: Private key XA used to sign; public key YA used to verify via modular exponentiation
⚡
ElGamal Signature Memory Trick — "S1 is α^k, S2 solves for M"

S1 = α^k mod q (simple power, like ElGamal encryption's C1).
S2 = k⁻¹(M - XA·S1) mod (q-1) — "solve k⁻¹ × (message minus key×S1)".
Verification: V1 = α^M, V2 = YA^S1 × S1^S2. Both should equal α^M mod q.
Important: k must be random and NEVER reused — same k twice → private key XA can be computed!

Schnorr Signature Scheme

70%

Schnorr Signature — Introduction

The Schnorr signature scheme, proposed by Claus Schnorr in 1989, is based on the discrete logarithm problem and is more efficient than ElGamal — the signature is smaller (320 bits for 160-bit security). Schnorr signatures are the mathematical basis for modern ECDSA and Bitcoin's signature scheme.

Schnorr is like a smarter, leaner version of ElGamal signatures. It produces a smaller signature and uses a hash function directly in the signing process — making it harder to forge. It's also simpler to understand mathematically.
🔗
Connection — Schnorr → DSA (Section 11)

DSA (the NIST standard you MUST know for exams) is directly based on Schnorr signatures. NIST adapted Schnorr's scheme to create DSA in 1991. If you understand Schnorr, DSA is just "Schnorr with slightly different parameter choices." Learn Schnorr → DSA clicks immediately.

Schnorr Signature — Parameters and Keys

Global Parameters (shared by all users)
p = large prime (≥ 512 bits) such that discrete log in Z*p is hard
q = prime factor of (p-1) with q ≥ 160 bits
g = integer with order q mod p, i.e., g = h^((p-1)/q) mod p for some h
These are the same structure as DSA parameters — study this once, applies to both!
User Keys
Private key: s where 0 < s < q (chosen randomly)
Public key: v = g^(-s) mod p = (g^s)^(-1) mod p

Schnorr Signature — Signing and Verification ⭐⭐

Signing (Message M)
Step 1: Choose random r where 0 < r < q
Step 2: Compute x = g^r mod p
Step 3: Compute e = H(M || x) ← hash of message concatenated with x
Step 4: Compute y = (r + s×e) mod q
Signature = (e, y) | Note: e is the "challenge" hash, y is the "response"
Verification
Step 1: Compute x' = g^y × v^e mod p
Step 2: Compute e' = H(M || x')
Step 3: If e' = e → Signature is VALID ✅
Mathematical basis: g^y × v^e = g^(r+s·e) × g^(-s·e) = g^r = x (mod p)

🔥 95% — MOST IMPORTANT
🔮

DSA — Introduction

The Digital Signature Algorithm (DSA) was proposed by NIST in 1991 and standardized as FIPS PUB 186 (Digital Signature Standard, DSS). It is based on the discrete logarithm problem and is a variant of the ElGamal and Schnorr signature schemes. DSA is designed purely for digital signatures — unlike RSA, it cannot be used for encryption.

DSA is the government-certified, official way to create digital signatures. Think of it as the "passport" of cryptographic signatures — NIST (the US standards body) certified it, and it's used in everything from software code signing to government documents. Unlike RSA which can both encrypt AND sign, DSA does signatures only — but it does them very efficiently.

DSA — Global Parameters (chosen by system, shared by all)

Global Parameters
p = prime with 2^(L-1) < p < 2^L where L is 512 to 1024 bits (multiple of 64)
q = prime factor of (p-1) with 2^159 < q < 2^160 (160-bit prime)
g = h^((p-1)/q) mod p where h is any integer with 1 < h < (p-1) and g > 1
p is a large prime, q is a 160-bit prime divisor of (p-1), g has order q mod p

DSA — User Key Generation

Per-User Key Generation
Private key: x where 0 < x < q (chosen randomly)
Public key: y = g^x mod p
Private key x is secret | Public key y is shared | Keys are generated once, used for many messages

DSA — Signing Algorithm ⭐⭐⭐

DSA Signing (Message M, using SHA as hash H)
Step 1: Choose random per-message k where 0 < k < q
Step 2: r = (g^k mod p) mod q
Step 3: s = k⁻¹ (H(M) + x·r) mod q
If r = 0 or s = 0, choose a different k and restart
Signature = (r, s) | k must be unique per message — NEVER reuse!

DSA — Verification Algorithm ⭐⭐⭐

DSA Verification (Signature (r,s), Message M, Public key y)
Step 1: w = s⁻¹ mod q (modular inverse of s)
Step 2: u1 = H(M) × w mod q
Step 3: u2 = r × w mod q
Step 4: v = (g^u1 × y^u2 mod p) mod q
Step 5: If v = r → Signature VALID ✅ | If v ≠ r → Signature INVALID ❌
Mathematical basis: w = s⁻¹ → u1 = H(M)/s → u2 = r/s → g^u1 × y^u2 = g^(H(M)/s) × g^(xr/s) = g^((H(M)+xr)/s) = g^k → mod q = r
Fig 11.1 — DSA: Signing uses private key x and random k; Verification uses public key y, global params p,q,g
⚡
DSA Memory Trick — "r, s sign; w, u1, u2, v verify"

Signing: r = (g^k mod p) mod q [first mod then mod again!] | s = k⁻¹(H(M) + xr) mod q [key times r, plus hash, times k-inverse]
Verification: w = s⁻¹ | u1 = H(M)·w | u2 = r·w | v = (g^u1 · y^u2 mod p) mod q | Compare v with r.
Key fact: v = r because g^u1 · y^u2 = g^(H(M)/s) · g^(xr/s) = g^((H(M)+xr)/s) = g^k → mod p mod q = r. This is the math behind the magic!

✅
DSA Answer Validation — Check These Points for Full Marks

1. Global params: p (large prime), q (160-bit prime divisor of p-1), g (generator of order q)
2. Public key y = g^x mod p — not (g^x mod p) mod q
3. r = (g^k mod p) mod q — double mod! Many students miss the second mod q
4. s = k⁻¹(H(M) + x·r) mod q — "H(M) + x times r, times k-inverse"
5. Verification has 4 steps: w → u1,u2 → v — many students miss one step

Digital Signature Algorithm (DSA) was proposed by NIST in 1991, standardized as FIPS PUB 186 (Digital Signature Standard). Based on discrete logarithm problem. Produces digital signatures that provide authentication, integrity, and non-repudiation. Cannot be used for encryption — signature only.

What happens if k is compromised?
If an attacker learns the value of k used to create signature (r, s) for message M:

From the signing equation: s = k⁻¹(H(M) + x·r) mod q
→ s·k = H(M) + x·r (mod q)
→ x·r = s·k - H(M) (mod q)
→ x = r⁻¹(s·k - H(M)) mod q

The attacker can directly compute the signer's private key x!

This means:
1. All past signatures can be forged (attacker now knows x)
2. Future messages can be signed with x
3. The compromise of a single k compromises the entire signing key

Example — Sony PS3 hack (2010): Sony used a constant k (not random) for all PS3 game signatures. Hackers extracted k from two different (M, signature) pairs, computed Sony's private key, and began signing pirated games with Sony's own key. This is why k MUST be cryptographically random and NEVER reused.

Q. Explain the application of cryptographic hash function for digital signature.
2025 Part B Q7 · 4 marks ⭐Hash + Digital Signature
Why Hash Functions Are Used in Digital Signatures:

Digital signatures operate on the hash of a message rather than the full message for two key reasons:

1. Efficiency: RSA, ElGamal, and DSA work on fixed-size numbers. A message M could be megabytes large. Computing a 10 MB document's RSA signature would be extremely slow. Instead, hash H(M) is computed (always 256 or 512 bits), and the signature is applied to this small fixed-size digest — much faster.

2. Security (Second Preimage Resistance): If you sign H(M) instead of M directly, the collision resistance property of the hash function ensures an attacker cannot find M' ≠ M with H(M') = H(M). If they could, they'd have a valid signature for a fraudulent document M'.

How it works:
Sender: h = H(M) using SHA-256 → S = Sign(h, private_key)
Receiver: h' = Verify(S, public_key) AND h = H(M received) → if h' = h → valid

Hash properties required for digital signatures:
• One-way: Cannot recover M from H(M) — private key not revealed by signature
• Collision-resistant: Cannot forge a different document with same signature
• Fixed output size: Efficient signing regardless of message length

Example: In DSA, s = k⁻¹(H(M) + x·r) mod q. The H(M) directly appears in the signature formula — the hash is an integral part of DSA's security proof.
