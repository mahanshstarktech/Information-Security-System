Public Key Cryptography — Introduction

85%

What is Public Key Cryptography?

Public Key Cryptography (also called Asymmetric Cryptography) uses two mathematically related keys: a public key (known to everyone) for encryption, and a private key (known only to the owner) for decryption. Unlike symmetric cryptography (DES, AES), the two keys are different — knowledge of the public key does not computationally reveal the private key.

Think of a mailbox: anyone can drop a letter through the slot (encrypt with your public key), but only you have the key to open the box and read the letters (decrypt with your private key). Or: a bank safe-deposit box — the bank can lock it (public key), but only you can open it (private key).
Asymmetric Cryptography — Key Pair
Key Pair: (PU_A, PR_A) — Public key and Private key of user A
Encryption: C = E(PU_B, M) ← Encrypt M using B's PUBLIC key
Decryption: M = D(PR_B, C) ← Decrypt C using B's PRIVATE key
Digital Sig: S = E(PR_A, M) ← Sign using A's PRIVATE key
Verify Sig: M = D(PU_A, S) ← Verify using A's PUBLIC key
Critical: knowledge of E and PU must NOT reveal PR (computationally infeasible to invert)
🔗
Unit 3 (Symmetric) → Unit 4 (Asymmetric) — Key Difference

Unit 3 (DES/AES) = symmetric: same key for encrypt and decrypt. Key distribution problem: both parties must secretly share the same key before communicating — hard over untrusted network.
Unit 4 = asymmetric: different keys. Public key can be freely shared. Solves key distribution problem — anyone can encrypt to you using your public key, only you can decrypt. Trade-off: 100–1000× slower than symmetric. Real systems (TLS/SSL from Unit 6) use asymmetric to exchange a session key, then switch to symmetric for bulk data.

Requirements & Cryptanalysis of Public Key

80%

Requirements of Public Key Cryptosystem (Diffie-Hellman 1976)

For a public key cryptosystem to be secure and practical, it must satisfy these requirements:

  1. Key Generation Efficiency: It must be computationally easy (polynomial time) for user B to generate their key pair (PU_B, PR_B).
  2. Encryption Efficiency: It must be computationally easy for sender A to produce ciphertext C = E(PU_B, M) given B's public key and plaintext M.
  3. Decryption Efficiency: It must be computationally easy for B to recover M = D(PR_B, C) using their private key.
  4. Private Key Infeasibility: It must be computationally infeasible for an adversary knowing PU_B to determine PR_B. (The "trapdoor one-way function" property)
  5. Plaintext Recovery Infeasibility: It must be computationally infeasible for an adversary knowing PU_B and C to recover M without knowing PR_B.
  6. Optional — Commutativity: E(PR_B, E(PU_B, M)) = E(PU_B, E(PR_B, M)) = M (not required but useful for digital signatures — RSA satisfies this).
Trapdoor One-Way Function — The Core Concept
One-way: Easy to compute f(x), computationally infeasible to compute f⁻¹(y)
Trapdoor: With secret information (private key), f⁻¹(y) becomes easy
RSA trapdoor: factoring large numbers is hard; but knowing the prime factors makes decryption easy
ElGamal trapdoor: computing discrete logarithm is hard; but knowing the secret x makes decryption easy

Cryptanalysis of Public Key Systems

Public key systems are attacked differently from symmetric systems. Since the public key is known, an attacker can launch specific mathematical attacks:

  • Brute-force Attack: Try all possible private keys. Countered by large key sizes (RSA: 2048+ bits recommended).
  • Mathematical Attack on Underlying Problem:
    • RSA → Integer Factorization Problem (IFP): factor n = p×q. Best known algorithm (General Number Field Sieve) takes sub-exponential time for 512-bit n, but infeasible for 2048-bit.
    • ElGamal/Diffie-Hellman → Discrete Logarithm Problem (DLP): find x given αˣ mod q. Index calculus method is best known.
    • ECC → Elliptic Curve Discrete Logarithm Problem (ECDLP): harder than DLP — 256-bit ECC ≈ 3072-bit RSA in security.
  • Chosen Ciphertext Attack: Attacker submits chosen ciphertexts and gets decryptions — RSA without padding (textbook RSA) is vulnerable. Countered by RSA-OAEP padding.
  • Timing Attack: Measure time taken for decryption to deduce private key bits. Countered by constant-time implementations.
  • Man-in-the-Middle Attack (MITM): Specifically attacks key exchange (Diffie-Hellman) — covered in next section.

🔮

Diffie-Hellman — The Problem It Solves

Diffie-Hellman Key Exchange (1976) was the first publicly known asymmetric protocol. It solves the key distribution problem: how can two parties establish a shared secret key over an insecure (public) channel without ever having communicated before? The answer: use properties of modular arithmetic (specifically, the Discrete Logarithm Problem).

Imagine mixing paint. Yellow and blue make green. If Alice starts with yellow (her private key) and Bob starts with blue (his private key), and they publicly share the combined colour (public keys), they can each make the same shade of green (shared secret) without revealing their individual starting colours. Even if an eavesdropper sees both intermediate colours, they can't easily figure out the original yellow or blue.
Diffie-Hellman — Global Parameters and Key Exchange
Global public parameters: q (large prime), α (primitive root of q, 1 ≤ α ≤ q-1)
Alice's private key: X_A (random, 1 ≤ X_A ≤ q-2, kept secret)
Alice's public key: Y_A = α^X_A mod q ← Alice publishes this
Bob's private key: X_B (random, kept secret)
Bob's public key: Y_B = α^X_B mod q ← Bob publishes this
Shared secret key (Alice): K = Y_B^X_A mod q = (α^X_B)^X_A mod q = α^(X_A·X_B) mod q
Shared secret key (Bob): K = Y_A^X_B mod q = (α^X_A)^X_B mod q = α^(X_A·X_B) mod q
Both Alice and Bob independently compute the SAME shared key K = α^(X_A·X_B) mod q
Security: attacker sees q, α, Y_A, Y_B but must solve X_A from Y_A = α^X_A mod q (Discrete Log Problem)

Diffie-Hellman — Worked Numerical Example

📌 Numerical — Standard DH Example (practice this for any given values)

Let q = 23, α = 5 (primitive root of 23)
Alice chooses X_A = 6 (private). Computes Y_A = 5⁶ mod 23.
5¹=5, 5²=25 mod23=2, 5³=10, 5⁴=50 mod23=4, 5⁵=20, 5⁶=100 mod23=100-4×23=100-92=8
Y_A = 8 (Alice publishes 8)

Bob chooses X_B = 15 (private). Computes Y_B = 5¹⁵ mod 23.
5⁶=8, 5¹²=8²=64 mod23=18, 5¹⁵=5¹²×5³=18×10=180 mod23=180-7×23=180-161=19
Y_B = 19 (Bob publishes 19)

Alice computes K = Y_B^X_A mod 23 = 19⁶ mod 23
19²=361 mod23=361-15×23=361-345=16; 19⁴=16²=256 mod23=256-11×23=3; 19⁶=3×16=48 mod23=2
K_Alice = 2

Bob computes K = Y_A^X_B mod 23 = 8¹⁵ mod 23
8²=64 mod23=18; 8⁴=18²=324 mod23=324-14×23=2; 8⁸=2²=4; 8¹⁵=8⁸×8⁴×8²×8=4×2×18×8=1152 mod23=1152-50×23=2
K_Bob = 2 ✓ — Both independently derive K = 2!

⚡
DH Numerical Fast Trick — Repeated Squaring

For large exponents, use repeated squaring (square-and-multiply):
To compute 5¹⁵ mod 23: 15 in binary = 1111
Start: result=1, base=5 mod 23=5
Bit 1 (LSB): result = result×5=5; base=5²=25mod23=2
Bit 1: result=5×2=10; base=2²=4
Bit 1: result=10×4=40mod23=17; base=4²=16
Bit 1(MSB): result=17×16=272mod23=272-11×23=19 ✓
This avoids computing huge intermediate numbers.

Man-in-the-Middle (MITM) Attack on Diffie-Hellman

DH is vulnerable to MITM attack because it provides no authentication — Alice and Bob cannot verify who they're actually talking to. An attacker Darth can intercept and replace the public keys.

1
Alice sends her public key Y_A = α^X_A mod q to Bob.
2
Darth (MITM) intercepts Y_A. Darth generates his own private key X_D and computes Y_D = α^X_D mod q.
3
Darth sends Y_D to Bob (pretending to be Alice). Bob computes shared key K2 = Y_D^X_B mod q (actually a key with Darth, not Alice!).
4
Bob sends his public key Y_B. Darth intercepts it and sends Y_D to Alice (pretending to be Bob).
5
Alice computes shared key K1 = Y_D^X_A mod q (actually a key with Darth!). Now Darth shares K1 with Alice and K2 with Bob — can decrypt, read, re-encrypt all messages.
Fig 3.1 — DH MITM Attack: Darth intercepts both public keys and substitutes his own. Alice and Bob each think they share a key with each other, but actually each shares a different key with Darth.

How to defend against MITM on DH: Use authenticated Diffie-Hellman — combine DH with digital certificates (X.509, from Unit 6). Each party signs their public key with a trusted Certificate Authority. An attacker cannot substitute a fake public key because it won't have the CA's signature. This is exactly what TLS/HTTPS does (Unit 6).

Q. What is a primitive root? Explain the Diffie-Hellman key exchange algorithm with a proper example. Discuss the man-in-the-middle attack problem associated with the algorithm.

Primitive Root:
A primitive root of a prime q is an integer α such that the set {α¹ mod q, α² mod q, ..., α^(q-1) mod q} generates all values {1, 2, ..., q-1}. In other words, α is a generator of the multiplicative group Z*_q.
Example: q=7, α=3: 3¹=3, 3²=2, 3³=6, 3⁴=4, 3⁵=5, 3⁶=1 → generates {1,2,3,4,5,6} ✓ → 3 is a primitive root of 7.
Check α=2 for q=7: 2¹=2, 2²=4, 2³=1, 2⁴=2... → only {1,2,4} generated → NOT a primitive root.

Diffie-Hellman Key Exchange Algorithm:
Security basis: Discrete Logarithm Problem (DLP) — given αˣ mod q, find x is computationally infeasible for large q.

Setup: Both parties agree on public parameters: q (large prime), α (primitive root of q).

Alice: Choose secret X_A. Compute Y_A = α^X_A mod q. Publish Y_A.
Bob: Choose secret X_B. Compute Y_B = α^X_B mod q. Publish Y_B.

Shared key: Alice computes K = Y_B^X_A mod q. Bob computes K = Y_A^X_B mod q.
Both get K = α^(X_A·X_B) mod q ← the shared secret!

Example (q=23, α=5, X_A=6, X_B=15):
Y_A = 5⁶ mod 23 = 8; Y_B = 5¹⁵ mod 23 = 19
Alice: K = 19⁶ mod 23 = 2; Bob: K = 8¹⁵ mod 23 = 2 ✓

[Draw: Alice ← q,α,Y_A,Y_B → Bob with Darth in the middle for MITM]

Man-in-the-Middle (MITM) Attack:
Step 1: Alice computes Y_A = α^X_A mod q and sends to Bob.
Step 2: Darth intercepts Y_A. Creates own X_D, computes Y_D = α^X_D mod q.
Step 3: Darth sends Y_D to Bob (faking Alice). Bob computes K2 = Y_D^X_B mod q (shared with Darth, not Alice!).
Step 4: Bob sends Y_B to Alice. Darth intercepts, sends Y_D to Alice (faking Bob).
Step 5: Alice computes K1 = Y_D^X_A mod q (shared with Darth, not Bob!).
Result: Darth shares K1 with Alice and K2 with Bob. All messages can be decrypted and re-encrypted by Darth. Alice and Bob believe they communicate securely but Darth reads everything.

Why DH is vulnerable: DH provides no authentication — it cannot verify the identity of the party holding the public key.

Defense: Authenticated DH using digital certificates (PKI). TLS/HTTPS signs DH public keys with X.509 certificates from a trusted CA — an attacker's fake key won't have a valid CA signature.
Q. What is Primitive Root? Explain an algorithm to determine Primitive roots. Determine all the Primitive roots of 19.
2023-Aug Part B Q4 · 4 marks ⭐⭐Primitive Root
Primitive Root: An integer α is a primitive root of prime q if α generates all elements {1, 2, ..., q-1} when raised to successive powers modulo q. Formally, the smallest positive integer k such that α^k ≡ 1 (mod q) is k = q-1 (the order equals φ(q)).

Algorithm to find primitive roots of prime q:
1. Find all prime factors of (q-1). Let them be p₁, p₂, ..., pₖ.
2. For each candidate α (from 2 to q-1):
  a. For each prime factor pᵢ: compute α^((q-1)/pᵢ) mod q
  b. If ALL results ≠ 1, then α IS a primitive root.
  c. If ANY result = 1, then α is NOT a primitive root.
3. The number of primitive roots of prime q = φ(q-1)

Find all primitive roots of q = 19:
q-1 = 18 = 2 × 3² → prime factors: {2, 3}
φ(18) = φ(2)×φ(3²) = 1×6 = 6 → there are 6 primitive roots

Test α=2: 2^(18/2)=2⁹=512 mod19=512-26×19=18≠1 ✓; 2^(18/3)=2⁶=64 mod19=7≠1 ✓ → 2 IS a primitive root
Test α=3: 3⁹ mod19=3⁹. 3²=9,3⁴=81mod19=5,3⁸=25mod19=6,3⁹=18 ≠1 ✓; 3⁶=6×9=54mod19=16≠1 ✓ → 3 IS a primitive root
Test α=4: 4⁹=2¹⁸mod19=1 → 4 is NOT (since 2¹⁸≡1 mod 19 by Fermat's little theorem only if order divides 18; 4=2² has order 9, not 18)
All 6 primitive roots of 19: {2, 3, 10, 13, 14, 15}

(Verify: the primitive roots are 2^k mod 19 for gcd(k,18)=1, i.e., k∈{1,5,7,11,13,17})

RSA — Introduction

RSA (Rivest, Shamir, Adleman — MIT, 1978) is the most widely used public key cryptosystem. Its security is based on the Integer Factorization Problem (IFP): given n = p×q (product of two large primes), finding p and q is computationally infeasible for large n (2048+ bits in practice).

RSA is like creating a padlock that anyone can close (encrypt) but only you can open (decrypt). The lock is built from two giant prime numbers multiplied together — anyone can use n=p×q to lock data, but only someone who knows the original primes p and q can unlock it. Finding p and q from n alone (factoring) would take longer than the age of the universe for large n.

RSA — Key Generation Algorithm ⭐⭐⭐

1
Choose two large distinct primes p and q.
In exam: given small values like p=3, q=11 or p=5, q=31.
2
Compute n = p × q (the modulus). n is made public.
3
Compute φ(n) = (p-1)(q-1) (Euler's totient function). This is kept private.
4
Choose public exponent e such that: 1 < e < φ(n) AND gcd(e, φ(n)) = 1 (e is coprime to φ(n)).
Common choices: e = 3, 17, 65537 (in practice).
5
Compute private key d = e⁻¹ mod φ(n) (multiplicative inverse of e modulo φ(n)).
Find d such that: e × d ≡ 1 (mod φ(n)). Use Extended Euclidean Algorithm.
RSA — Key Pairs and Operations
Public Key: PU = {e, n} ← share freely
Private Key: PR = {d, n} ← keep secret
Encryption: C = M^e mod n (M = plaintext, 0 ≤ M < n)
Decryption: M = C^d mod n
Correctness: C^d = (M^e)^d = M^(ed) ≡ M (mod n) — this follows from Euler's theorem: M^φ(n) ≡ 1 (mod n)
Digital Signature: S = M^d mod n (sign with private key); Verify: M = S^e mod n (recover with public key)
⚡
RSA Exam Trick — Finding d using Extended Euclidean

To find d = e⁻¹ mod φ(n), use the Extended Euclidean Algorithm.
Example: e=7, φ(n)=20. Find d: we need 7d ≡ 1 (mod 20).
Method: Try d = 1, 2, 3... until 7d mod 20 = 1.
d=3: 21 mod 20 = 1 ✓ → d=3.
Or use formula: d = (1 + k×φ(n))/e for integer k.
k=1: (1+20)/7 = 3. Integer → d=3.
k=2: (1+40)/7 = 5.8 → not integer. k=3: (1+60)/7 = 61/7 → not integer. Continue until integer found.

RSA — Security and Attacks

  • Integer Factorization Attack: Factor n = p×q. For 2048-bit n, this takes ~10²⁸ years with best algorithms. RSA-768 (232 digits) was factored in 2009 after 2 years — 2048-bit is recommended minimum today.
  • Chosen Ciphertext Attack: Textbook RSA without padding is malleable. If C = Mᵉ mod n, then for any s: (sᵉ × C) mod n decrypts to (s × M) mod n. Countered by OAEP padding.
  • Small e Attack: If e=3 and M is small, Mᵉ may be less than n, so C = Mᵉ (no modular reduction) → attacker takes cube root. Countered by padding.
  • Timing Attack: Measure decryption time to infer d. Countered by constant-time exponentiation.

Rabin Cryptosystem

Rabin — Introduction and Concept

The Rabin cryptosystem (Michael Rabin, 1979) is a variant of RSA where the encryption exponent is fixed at e=2 (squaring instead of arbitrary exponentiation). Its security is provably equivalent to the difficulty of factoring n — unlike RSA where this equivalence is not formally proven.

Rabin is like RSA's simpler cousin. Instead of raising M to a large power e, you just square it: C = M² mod n. It's mathematically proven that breaking Rabin = factoring n, which makes it theoretically more secure than RSA. But the "catching up" happens during decryption — squaring is not one-to-one, so you always get four possible plaintexts and must figure out which is the real one.
Rabin Cryptosystem
Key Generation: Choose p, q (distinct primes ≡ 3 mod 4 for easy decryption)
n = p × q (public key)
(p, q) = private key
Encryption: C = M² mod n (squaring only — no public exponent to choose!)
Decryption: Solve M² ≡ C (mod n) using Chinese Remainder Theorem
→ gives 4 possible roots: ±m_p mod n, ±m_q mod n
Problem: Decryption gives 4 possible plaintexts — must identify correct one (add redundancy to plaintext)
Security: Provably equivalent to integer factorization (unlike RSA where this is only conjectured)
Why p,q ≡ 3 (mod 4)? Makes square root computation: m_p = C^((p+1)/4) mod p (efficient)

Rabin Decryption — Using CRT

Given C = M² mod n, to find M, use the Chinese Remainder Theorem:

1
Compute m_p = C^((p+1)/4) mod p (square root of C mod p, works when p ≡ 3 mod 4)
2
Compute m_q = C^((q+1)/4) mod q (square root of C mod q)
3
Apply CRT: Find the four square roots of C mod n:
r = y_p×p×m_p + y_q×q×m_q mod n
s = n - r
t = y_p×p×m_p - y_q×q×m_q mod n
u = n - t
where y_p = (q⁻¹ mod p) and y_q = (p⁻¹ mod q)
4
Four candidates: {r, s, t, u} mod n — use redundancy in plaintext to identify correct M.
💡
Rabin vs RSA — Key Comparison for Exam

Rabin: C = M² mod n (e=2 always) | 4 decryption candidates | Provably = factoring | Less practical (ambiguous decryption).
RSA: C = Mᵉ mod n (e arbitrary) | Unique decryption | Conjectured = factoring (not proven) | More practical.
If asked "advantage of Rabin over RSA": provable security reduction. If asked "disadvantage": ambiguous decryption (4 possible plaintexts). These two points alone fill a 2-mark answer.

ElGamal — Introduction

The ElGamal cryptosystem (Taher ElGamal, 1985) is a public key algorithm based on the Discrete Logarithm Problem (DLP): given α^x mod q, finding x is computationally infeasible for large q. Unlike RSA (fixed ciphertext for a given M), ElGamal is probabilistic — the same M encrypted twice with different k values gives different ciphertext pairs.

ElGamal works like a special kind of padlock using the mathematics of "clocks" (modular arithmetic). You pick a public prime clock face (q), a starting position (α), and your secret rotation (X_A). Anyone can encrypt by adding a one-time random rotation (k), but only you — knowing your secret X_A — can subtract it back out to read the message.

ElGamal — Complete Algorithm ⭐⭐⭐

Key Generation:

ElGamal — Key Generation
Choose: q (large prime), α (primitive root of q), X_A (private key, random, 1 ≤ X_A ≤ q-2)
Public key: Y_A = α^X_A mod q
Public parameters: {q, α, Y_A} ← share these
Private key: X_A ← keep secret

Encryption (by sender B, sending M to A):

ElGamal — Encryption (5 steps)
Step 1: Choose random k (1 ≤ k ≤ q-2, k kept secret after use)
Step 2: Compute one-time key: K = Y_A^k mod q = (α^X_A)^k mod q
Step 3: Compute C1 = α^k mod q
Step 4: Compute C2 = K × M mod q (or C2 = M × K mod q)
Step 5: Ciphertext = (C1, C2) ← send both values to A
Key insight: Without knowing X_A, attacker cannot compute K from C1=α^k (DLP problem)

Decryption (by receiver A):

ElGamal — Decryption
Received: (C1, C2)
Step 1: Compute K = C1^X_A mod q = (α^k)^X_A mod q = α^(k·X_A) mod q
Step 2: M = C2 × K⁻¹ mod q = C2 × K^(q-2) mod q
(since K × K⁻¹ ≡ 1 mod q, we have M = C2/K mod q)
K⁻¹ mod q = K^(q-2) mod q (by Fermat's Little Theorem: K^(q-1) ≡ 1 mod q)
⚡
ElGamal 5-Step Memory Formula — Never Forget

KKCCC: Generate K=Y_A^k mod q, Compute C1=α^k mod q, Compute C2=K×M mod q → Ciphertext=(C1,C2).
Decrypt: KKM: K=C1^X_A mod q → M = C2×K⁻¹ mod q = C2×K^(q-2) mod q.
Key verify: Always check C1^X_A mod q = Y_A^k mod q (should give the same K). If they match — you've done it right!

Q. Explain ElGamal digital signature algorithm.
2023-Jul Part B Q5 · 4 marks ⭐⭐ElGamal Signature
ElGamal Digital Signature Algorithm:

Parameters: Large prime q, primitive root α, private key X_A, public key Y_A = α^X_A mod q.

Signing (by sender A):
1. Choose random k (gcd(k, q-1)=1, keep secret)
2. Compute S1 = α^k mod q
3. Compute S2 = k⁻¹ × (M - X_A × S1) mod (q-1)
4. Signature = (S1, S2)

Verification (by receiver B):
Compute V1 = α^M mod q
Compute V2 = Y_A^S1 × S1^S2 mod q
Signature is valid if V1 = V2.

Why it works:
V2 = Y_A^S1 × S1^S2 = (α^X_A)^S1 × (α^k)^S2
= α^(X_A×S1) × α^(k×S2)
= α^(X_A×S1 + k×S2)
S2 = k⁻¹(M - X_A×S1) → k×S2 = M - X_A×S1
→ exponent = X_A×S1 + M - X_A×S1 = M
→ V2 = α^M = V1 ✓

Security: Forging a signature requires finding k (discrete log) or finding a collision in the signing equation — both computationally infeasible.

ECC — Introduction and Motivation

Elliptic Curve Cryptography (ECC) applies the Discrete Logarithm Problem (DLP) to points on an elliptic curve over a finite field — the ECDLP (Elliptic Curve DLP). ECDLP is harder than regular DLP, meaning equivalent security can be achieved with much shorter keys: 256-bit ECC ≈ 3072-bit RSA in security level.

Instead of working with regular numbers and multiplication (like RSA), ECC uses a special curved shape (an elliptic curve). Points on this curve can be "added" together in a special mathematical way. The one-way problem: given a starting point G and the result P = k×G, finding k is extremely hard. Short keys (256 bits) provide the same security as RSA with 3072-bit keys — much more efficient for mobile devices and IoT.
Elliptic Curve — General Equation (Weierstrass Form)
y² = x³ + ax + b (over real numbers or finite field GF(p) or GF(2^m))
Condition: 4a³ + 27b² ≠ 0 (non-singular — no cusps or self-intersections)
For cryptography: use E over GF(p) — all coordinates are integers mod p
Key sizes: 256-bit ECC ≈ 3072-bit RSA ≈ 128-bit AES in security

Point Addition and Scalar Multiplication on Elliptic Curves

The fundamental operation in ECC is point addition (adding two curve points to get a third) and scalar multiplication (adding a point to itself k times: P + P + ... + P = kP).

ECC Point Addition: P + Q = R (where P≠Q, P≠-Q)
Slope: λ = (y_Q - y_P) / (x_Q - x_P) mod p
x_R = λ² - x_P - x_Q mod p
y_R = λ(x_P - x_R) - y_P mod p
Special case (P=Q, Point Doubling): λ = (3x_P² + a) / (2y_P) mod p
Point at Infinity O: identity element (P + O = P for all P)
Inverse: -P = (x_P, -y_P mod p)

ECC Diffie-Hellman Key Exchange (ECDH)

The standard way to use ECC for key exchange:

ECDH — Analogous to Regular Diffie-Hellman
Global: Elliptic curve E, generator point G, prime q
Alice: Private n_A (integer). Public P_A = n_A × G
Bob: Private n_B (integer). Public P_B = n_B × G
Shared secret: Alice: n_A × P_B = n_A × n_B × G
Bob: n_B × P_A = n_B × n_A × G ← same!
ECDLP: Given G and P_A = n_A × G, finding n_A is computationally infeasible

Why ECC over RSA?
