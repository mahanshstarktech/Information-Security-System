Block Ciphers — Introduction

What is a Block Cipher?

A block cipher is a symmetric encryption algorithm that operates on fixed-size blocks of plaintext at a time (e.g., 64 bits for DES, 128 bits for AES) and uses a secret key to produce a fixed-size block of ciphertext of the same length.

A block cipher is like a combination lock that takes your message, chops it into equally-sized pieces (blocks), and scrambles each piece using a secret key. Give the same block with the same key, you always get the same scrambled output. Change even one letter — the output is completely different.
Block Cipher — Mathematical Model
C = E(K, P) ← Encryption: Plaintext P + Key K → Ciphertext C
P = D(K, C) ← Decryption: Ciphertext C + Key K → Plaintext P
E and D are inverse functions: D(K, E(K, P)) = P for all P and K
DES: block = 64 bits, key = 56 bits | AES: block = 128 bits, key = 128/192/256 bits

Feistel Cipher — Foundation of DES

The Feistel Cipher is a symmetric structure used in block cipher design. It splits the plaintext block into two halves (L and R) and applies multiple rounds of a round function F using subkeys. The beauty of Feistel is that the same structure is used for both encryption and decryption — only the key schedule is reversed.

Feistel is like a "shuffle and swap" machine. In each round, the right half goes through a blender (the round function F with a round key), and the result is XOR'd with the left half. Then the two halves swap sides. Repeat 16 times. To decrypt, just run the same machine backwards using the keys in reverse order.
Feistel Cipher — One Round
Input: (Lᵢ₋₁, Rᵢ₋₁)
Lᵢ = Rᵢ₋₁ ← Right becomes new Left
Rᵢ = Lᵢ₋₁ ⊕ F(Rᵢ₋₁, Kᵢ) ← Old Left XOR'd with F(Right, RoundKey)
⊕ = XOR | F = Round function | Kᵢ = Round subkey
Key insight: Decryption is identical structure — just use K₁₆, K₁₅, ..., K₁ (reverse key order)

Shannon's Principles — Confusion and Diffusion

Claude Shannon (1949) identified two key properties that a strong block cipher must have:

ConfusionMake the relationship between key and ciphertext as complex as possibleAttacker cannot deduce key even with many plaintext-ciphertext pairsS-boxes (non-linear substitution) in each roundSubBytes transformation (non-linear S-box)
DiffusionEach bit of plaintext should influence many bits of ciphertextSpread statistical structure of plaintext across ciphertextP-box permutation and expansion EShiftRows + MixColumns spread bits across the state
Confusion: make it impossible to guess the recipe (key) from the cake (ciphertext) — done by complex mixing. Diffusion: if you change one ingredient, the entire cake changes — done by spreading each bit's influence wide. DES and AES both use both principles in every round.
Avalanche Effect — Key Principle
A small change in input (1 bit) → drastic change in output (≈ 50% of bits flip)
DES: changing 1 plaintext bit → approximately 32 of 64 output bits change after full encryption
Avalanche effect ensures: complete ciphertext change even for tiny plaintext/key variations
This makes frequency analysis and differential attacks computationally infeasible

Design Principles of Block Cipher — RTU Answer Structure

  1. Confusion (Substitution): Replace plaintext elements with complex ciphertext elements via non-linear S-boxes. Breaks statistical relationship between key and ciphertext.
  2. Diffusion (Permutation/Transposition): Rearrange/mix bits so each input bit affects many output bits. Eliminates statistical patterns from plaintext.
  3. Feistel Structure: Split block into L and R halves; apply round function to one half and XOR with other; swap. Same structure for encrypt and decrypt (only key schedule reversed).
  4. Round Number: Multiple rounds ensure cumulative confusion and diffusion. DES: 16 rounds. AES: 10/12/14 rounds depending on key size. More rounds = more security but slower.
  5. Key Schedule: Derive multiple round subkeys from a single master key. Each round uses a different subkey — prevents simple patterns across rounds.
  6. Avalanche Effect: Changing 1 bit of plaintext or key should change approximately half the ciphertext bits. Ensures sensitivity to small changes.
  7. Non-linearity: S-boxes must be non-linear to resist linear and differential cryptanalysis. DES S-boxes were carefully designed by IBM/NSA for this purpose.
  8. Completeness: Each ciphertext bit must depend on every plaintext bit and key bit after sufficient rounds.

6. Key Schedule: Different subkeys are derived from the master key for each round, preventing simple patterns.

DES — Introduction

DES (Data Encryption Standard) was developed by IBM and adopted by NIST in 1977 as a US federal standard. It is a symmetric block cipher based on the Feistel structure, operating on 64-bit blocks with a 56-bit key (the actual key is 64 bits, but 8 bits are parity bits) and using 16 rounds of transformation.

DES is like a complex combination lock from 1977. You feed your data (in 64-bit chunks) into the machine, it performs 16 rounds of shuffling and substituting, and out comes scrambled data. The key is 56 bits — meaning there are 2⁵⁶ ≈ 72 quadrillion possible keys. In 1977 this was unbreakable; today a powerful computer can crack it in hours (DES is now obsolete).
DES Key Parameters
Block size: 64 bits (operates on 8 bytes of plaintext at a time)
Key size: 64 bits input → 56 effective bits (8 parity bits discarded via PC-1)
Rounds: 16 Feistel rounds
Round keys: 16 subkeys, each 48 bits (derived from 56-bit master key)
Decryption: use same algorithm, same IP/IP⁻¹, but apply subkeys in REVERSE order K₁₆→K₁

DES — Overall Structure (Steps 1–5)

1
Initial Permutation (IP): The 64-bit plaintext block is permuted according to a fixed table (IP table). This reorders the 64 bits — bit 58 goes to position 1, bit 50 to position 2, etc. This doesn't add security — it was originally intended for hardware implementation ease. Output: 64 permuted bits.
2
Split into L₀ and R₀: The 64-bit IP output is split into two 32-bit halves. L₀ = leftmost 32 bits, R₀ = rightmost 32 bits. These are the starting values for the 16 Feistel rounds.
3
16 Feistel Rounds: For each round i (1 to 16):
Lᵢ = Rᵢ₋₁
Rᵢ = Lᵢ₋₁ ⊕ F(Rᵢ₋₁, Kᵢ)
where F is the round function and Kᵢ is the 48-bit subkey for round i.
4
32-bit Swap: After all 16 rounds, the two halves are swapped: the output is R₁₆ concatenated with L₁₆ (note: right comes first). This swap ensures decryption works with the same algorithm.
5
Final Permutation (IP⁻¹): Apply the inverse of the Initial Permutation to the 64-bit (R₁₆ || L₁₆). This produces the 64-bit ciphertext. IP⁻¹ is the exact reverse permutation of IP.

DES — Internal Structure of Single Round

🔥 95% — Most Drawn Diagram
🔮

The Round Function F — Step by Step

The round function F takes a 32-bit right half Rᵢ₋₁ and a 48-bit subkey Kᵢ as input, and produces a 32-bit output. This output is XOR'd with Lᵢ₋₁ to form the new right half Rᵢ.

1
Expansion (E-box): The 32-bit right half Rᵢ₋₁ is expanded to 48 bits using the Expansion Permutation table E. Some bits are repeated — 16 bits appear twice. This allows each output bit to depend on more input bits (diffusion) and also matches the key length for XOR.
2
XOR with Subkey: The 48-bit expanded block is XOR'd with the 48-bit round subkey Kᵢ. This is where the key mixes into the data. Result: 48 bits.
3
Substitution (S-boxes): The 48-bit result is divided into 8 groups of 6 bits. Each 6-bit group is fed into one of 8 different Substitution Boxes (S₁ through S₈). Each S-box maps a 6-bit input to a 4-bit output using a lookup table. Output: 8×4 = 32 bits. This is the confusion step — the non-linear heart of DES security.
4
Permutation (P-box): The 32-bit S-box output is permuted according to a fixed P-box table. This shuffles the bits to ensure each bit of the S-box output affects multiple bits in the next round — this is the diffusion step. Output: 32 bits.
5
XOR with Left Half: The 32-bit P-box output is XOR'd with Lᵢ₋₁ (the left half from the previous round). This produces the new right half Rᵢ. The new left half Lᵢ is simply Rᵢ₋₁. The halves are ready for the next round.
DES Round Function F — Formula Chain
Step 1: E_out = E(Rᵢ₋₁) [32 bits → 48 bits, Expansion]
Step 2: XOR_out = E_out ⊕ Kᵢ [48 bits XOR 48-bit subkey]
Step 3: S_out = S₁(b₁)‖S₂(b₂)‖...‖S₈(b₈) [48→32 bits, 8 S-boxes]
Step 4: P_out = P(S_out) [32 bits → 32 bits, P-box permutation]
Step 5: Rᵢ = Lᵢ₋₁ ⊕ P_out [New Right = Old Left XOR F output]
Lᵢ = Rᵢ₋₁ [New Left = Old Right]
F(Rᵢ₋₁, Kᵢ) = P(S(E(Rᵢ₋₁) ⊕ Kᵢ)) — the complete round function
Fig 4.1 — DES Single Round: Rᵢ₋₁ → Expansion (32→48) → XOR Kᵢ → 8 S-boxes (48→32) → P-box → XOR Lᵢ₋₁ = Rᵢ | Lᵢ = Rᵢ₋₁

S-Boxes — The Heart of DES Security

The 8 Substitution Boxes (S-boxes) are the only non-linear component in DES — they are what make DES secure against mathematical attacks. Each S-box takes 6 bits of input and produces 4 bits of output using a predefined lookup table.

How to Use an S-Box (e.g., S₁)
Input: 6 bits = b₁b₂b₃b₄b₅b₆
Row: determined by b₁ and b₆ (the outer bits) → row = 2×b₁ + b₆ (value 0–3)
Column: determined by b₂b₃b₄b₅ (the inner 4 bits) → col = binary value 0–15
Output: look up the table at (row, column) → read the 4-bit value
Example: Input = 011011 → Row: b₁=0, b₆=1 → row = 01 = 1 | Col: b₂b₃b₄b₅ = 1101 = 13 → S₁[1][13] = 5 → Output = 0101
⚡
S-Box Exam Trick — Row/Column Selection

Remember: outer bits = row (b₁ and b₆), inner bits = column (b₂b₃b₄b₅). Many students mix this up. Write it as: "Row = first and last bit; Column = middle 4 bits." If given an S-box table in the exam, practice one look-up to verify you're reading row first then column.

DES Key Schedule — Generating 16 Subkeys

The 16 round subkeys (each 48 bits) are generated from the 64-bit key input using the following process:

1
PC-1 (Permuted Choice 1): The 64-bit key → 56 bits (8 parity bits removed). The 56 bits are split into two 28-bit halves: C₀ and D₀.
2
Circular Left Shift: For each round i (1–16), both Cᵢ₋₁ and Dᵢ₋₁ are shifted left by 1 or 2 positions according to a shift schedule (rounds 1,2,9,16 → shift 1; rest → shift 2).
3
PC-2 (Permuted Choice 2): The shifted Cᵢ and Dᵢ (total 56 bits) are combined and 8 bits are discarded to produce Kᵢ = 48 bits. This is the round subkey for round i.

Step 2 — XOR with Subkey:
The 48-bit expanded block is XOR'd with the 48-bit round subkey Kᵢ.

Purpose of S-boxes in DES:

S-boxes (Substitution Boxes) are the ONLY non-linear components in DES. They serve the following purposes:

1. Confusion: S-boxes create a complex, non-linear relationship between the key and the ciphertext. Without non-linearity, DES would be vulnerable to linear cryptanalysis — an attacker could solve a system of linear equations to find the key.

2. Non-linearity: Each S-box maps a 6-bit input to a 4-bit output in a non-linear fashion. This cannot be expressed as a simple XOR of input bits — the relationship is deliberately irregular.

3. Data compression: S-boxes reduce 6-bit input to 4-bit output (reducing 48 bits back to 32 bits), which fits the Feistel structure.

4. Security against differential cryptanalysis: The S-boxes in DES were carefully designed by IBM/NSA to resist differential cryptanalysis — they minimise the probability that a specific input difference leads to a predictable output difference.

5. Key mixing amplification: S-boxes non-linearly mix the XOR'd key bits into the data, making it extremely difficult to work backwards from ciphertext to determine the key.

Strength and Weakness of DES

72%

Strengths of DES

  • Widely studied and tested: Used for 20+ years, no known algebraic attack has broken it — only brute force works.
  • S-box design: The 8 non-linear S-boxes provide strong confusion; DES was designed to withstand differential cryptanalysis (which wasn't publicly known until 1990).
  • Avalanche effect: Any 1-bit change in plaintext or key causes ~50% of output bits to change after full encryption.
  • Implementation efficiency: Originally designed for efficient hardware implementation using the Feistel structure.
  • Meets Shannon's criteria: Both confusion (S-boxes) and diffusion (P-boxes, expansion) are strongly achieved.

Weaknesses of DES

  • Short key (56 bits): 2⁵⁶ ≈ 72 quadrillion key combinations — brute force in 22 hours with EFF's DES Cracker (1999). Unacceptable today.
  • Weak keys: 4 "weak keys" exist where K₁=K₂=...=K₁₆ (encryption = decryption). Also 6 pairs of "semi-weak keys."
  • Complementarity property: If C = E(K, P), then complement(C) = E(complement(K), complement(P)). This halves the brute-force effort from 2⁵⁶ to 2⁵⁵.
  • 64-bit block size: Small block size means birthday attack becomes practical for long messages (birthday bound at 2³² blocks ≈ 32 GB — short by modern standards).
  • S-box controversy: IBM/NSA modified the original S-boxes without full disclosure — raised concerns about possible trapdoors (though none have been found).

Q. How does key size strengthen DES algorithm?
2023-24 (61N0403) Part B Q4 · 4 marks ⭐⭐DES Key Size
Key Size and DES Security:

DES uses a 56-bit effective key. The number of possible keys = 2⁵⁶ ≈ 72 × 10¹⁵ (72 quadrillion) combinations.

How larger key size strengthens security:

1. Brute force resistance: For an attacker trying keys randomly, larger key space = exponentially more time required. DES with 56 bits took EFF's dedicated machine 22 hours (1999). With 128-bit key (AES), brute force would take longer than the age of the universe with all computers combined.

2. Rule of thumb: Each additional bit DOUBLES the key space. 57 bits = 2× harder than 56. 128 bits = 2⁷² times harder than 56 bits.

3. Multiple encryption (Triple DES): To extend DES, apply it 3 times with 2 or 3 keys → effective key length of 112 or 168 bits. Exponentially more difficult to brute-force.

4. Current recommendation: Keys should be at least 128 bits for symmetric encryption. AES provides 128/192/256 bit keys — DES's 56-bit key is now considered insecure for any serious application.

Why Multiple Encryption?

Single DES is broken (56-bit key = 2⁵⁶ brute force, cracked in hours). Rather than redesigning from scratch, multiple encryption applies DES multiple times with different keys to increase security. The result is Triple DES (3DES), which extended DES's life until AES was standardised in 2001.

If one lock is not enough, add two more. Triple DES is like locking a suitcase with three combination locks in sequence. Even if someone can crack one lock, they face two more — making it 2¹¹² times harder than one.
Triple DES (3DES) — Two Variants
3DES with 3 keys (168-bit key): C = E(K₃, D(K₂, E(K₁, P)))
3DES with 2 keys (112-bit key): C = E(K₁, D(K₂, E(K₁, P))) [K₁=K₃]
Decryption (3 keys): P = D(K₁, E(K₂, D(K₃, C)))
Pattern: Encrypt-Decrypt-Encrypt (EDE). Backward compatibility: if K₁=K₂=K₃, it reduces to single DES.
Why EDE not EEE? EDE allows backward compatibility with single DES when K₁=K₂=K₃

Meet-in-the-Middle Attack (Why Double DES is Insecure)

You might think applying DES twice (Double DES) with two keys gives 2⁵⁶ × 2⁵⁶ = 2¹¹² security. Wrong! The meet-in-the-middle attack breaks Double DES in 2⁵⁷ operations instead of 2¹¹².

Meet-in-the-Middle Attack
C = E(K₂, E(K₁, P)) → X = E(K₁, P) = D(K₂, C)
Attack: Encrypt P with all 2⁵⁶ values of K₁ → store all X values in table
Decrypt C with all 2⁵⁶ values of K₂ → compare with table
Complexity: 2⁵⁶ + 2⁵⁶ = 2⁵⁷ ← much less than 2¹¹²!
This attack works "in the middle" — finding X that matches from both sides simultaneously

AES — Introduction

AES (Advanced Encryption Standard) was selected by NIST in 2001 to replace DES. Based on the Rijndael cipher designed by Joan Daemen and Vincent Rijmen. AES is NOT a Feistel cipher — it uses a Substitution-Permutation Network (SPN) where all bits of the block are transformed in every round (unlike DES where only half the block changes per round).

AES is the modern, ultra-secure replacement for DES. While DES uses a 56-bit key and 16 rounds in a half-block Feistel structure, AES uses 128/192/256-bit keys and operates on the ENTIRE 128-bit block in every round. Think of DES as a tumbler lock from the 1970s; AES is a modern bank vault.
AES Key Parameters
Block size: 128 bits (16 bytes) — ALWAYS, regardless of key size
Key size: 128 bits (AES-128) | 192 bits (AES-192) | 256 bits (AES-256)
Rounds: 10 (AES-128) | 12 (AES-192) | 14 (AES-256)
State: 4×4 matrix of bytes (the 128-bit block arranged in rows)
Mnemonic: 128→10 rounds | 192→12 rounds | 256→14 rounds | Add 2 rounds per extra 64-bit key segment
🔗
DES → AES: Key Differences to Remember

DES: Feistel structure (half block per round) | 64-bit block | 56-bit key | 16 rounds | S-boxes: non-linear (6→4 bits) | Designed in secret by IBM/NSA.
AES: SPN structure (entire block per round) | 128-bit block | 128/192/256-bit key | 10/12/14 rounds | SubBytes: non-linear (8→8 bits) | Public competition and design.

AES State — The 4×4 Byte Matrix

AES operates on a State — a 4×4 array of bytes (16 bytes = 128 bits). The plaintext block is loaded into the state column by column, and all transformations operate on this state.

AES State Structure (128-bit block = 4×4 bytes)
State = | a₀₀ a₀₁ a₀₂ a₀₃ |
| a₁₀ a₁₁ a₁₂ a₁₃ |
| a₂₀ a₂₁ a₂₂ a₂₃ |
| a₃₀ a₃₁ a₃₂ a₃₃ |
Each aᵣc = one byte (8 bits) | Input bytes loaded column by column: a₀₀,a₁₀,a₂₀,a₃₀ then a₀₁,a₁₁...

AES — Overall Structure (One Round at a Time)

1
Initial Round Key Addition: XOR the 128-bit plaintext with the first round key (round 0 key). This ensures the output depends on the key from the very first step. AES always starts with a key XOR before any rounds.
2
Rounds 1 to N-1 (e.g., rounds 1–9 for AES-128): Each full round applies four transformations in sequence: (1) SubBytes, (2) ShiftRows, (3) MixColumns, (4) AddRoundKey. All four transformations applied in every round.
3
Final Round (round N, e.g., round 10 for AES-128): Same as regular rounds but MixColumns is OMITTED. Final round: SubBytes → ShiftRows → AddRoundKey. Omitting MixColumns makes encryption and decryption symmetric.
AES Round Structure Summary
Round 0: AddRoundKey(State, RoundKey[0])
Rounds 1 to N-1: SubBytes → ShiftRows → MixColumns → AddRoundKey
Final Round N: SubBytes → ShiftRows → AddRoundKey (NO MixColumns!)
Why no MixColumns in final round? To make AES decryption identical in structure to encryption (just different subkeys + inverse operations)

AES Transformation Functions

🔥 88%

1. SubBytes — Non-linear Substitution (Confusion)

SubBytes is the non-linear substitution step. Each byte of the State is replaced by another byte according to a fixed AES S-box (a 16×16 lookup table). The AES S-box is constructed using the multiplicative inverse in GF(2⁸) followed by an affine transformation — this makes it non-linear and immune to linear attacks.

SubBytes is like translating each letter using a secret codebook. Every one of the 16 bytes gets swapped for a completely different byte using the AES codebook (S-box). This is the confusion step — it makes the relationship between key and data complex.
SubBytes — How It Works
Each byte b in state: b' = S(b) = AES_SBOX[b]
AES S-box: 256-entry lookup table (16×16 matrix, values 0x00 to 0xFF)
S-box construction: b' = b⁻¹ in GF(2⁸) followed by affine transformation
The S-box is the SAME for all bytes — one table handles all 16 bytes of the state
Inverse S-box (InvSubBytes) exists for decryption
💡
SubBytes vs DES S-boxes — Key Difference for Exam

DES has 8 DIFFERENT S-boxes (S₁ to S₈), each 6→4 bits. AES has ONE S-box (8→8 bits), same table for all bytes. DES S-boxes: designed empirically by IBM/NSA. AES S-box: mathematically designed using GF(2⁸) inverse — provably non-linear with known algebraic structure.

2. ShiftRows — Cyclic Shift for Diffusion

ShiftRows cyclically shifts the bytes in each row of the State by different amounts. Row 0 is not shifted; row 1 shifts left by 1; row 2 shifts left by 2; row 3 shifts left by 3 byte positions.

ShiftRows is like shuffling rows of a grid — each row gets slid left by a different amount. Row 0 stays, row 1 slides one step, row 2 slides two steps, row 3 slides three steps. This mixes bytes from different columns, spreading the influence of each byte across the entire state (diffusion).
ShiftRows — Before and After
Before: | a₀₀ a₀₁ a₀₂ a₀₃ | (Row 0: no shift)
| a₁₀ a₁₁ a₁₂ a₁₃ | (Row 1: shift left 1)
| a₂₀ a₂₁ a₂₂ a₂₃ | (Row 2: shift left 2)
| a₃₀ a₃₁ a₃₂ a₃₃ | (Row 3: shift left 3)
After: | a₀₀ a₀₁ a₀₂ a₀₃ |
| a₁₁ a₁₂ a₁₃ a₁₀ |
| a₂₂ a₂₃ a₂₀ a₂₁ |
| a₃₃ a₃₀ a₃₁ a₃₂ |
Inverse (InvShiftRows): shift right instead of left. Purpose: after SubBytes, bytes from different columns are now mixed.

3. MixColumns — Mixing Within Each Column (Diffusion)

MixColumns multiplies each column of the State by a fixed 4×4 matrix over GF(2⁸). This ensures that each output byte depends on all 4 input bytes of the column — maximum diffusion within each column.

MixColumns takes each column of the 4×4 matrix and mixes all 4 bytes in that column together. After MixColumns, every output byte of the column has been influenced by every input byte of that column — like blending colours in a column so each result colour contains traces of all original colours.
MixColumns — Matrix Multiplication
For each column c: [s'₀c, s'₁c, s'₂c, s'₃c]ᵀ = M × [s₀c, s₁c, s₂c, s₃c]ᵀ
| 2 3 1 1 | | s₀c |
M = | 1 2 3 1 | × | s₁c | (in GF(2⁸))
| 1 1 2 3 | | s₂c |
| 3 1 1 2 | | s₃c |
All arithmetic in GF(2⁸) — multiplication by 2 = left shift + conditional XOR (not regular multiplication)
MixColumns is OMITTED in the final round — only SubBytes, ShiftRows, AddRoundKey remain
⚡
MixColumns Memory Trick — "The 2311 Matrix"

MixColumns uses the matrix [2,3,1,1 / 1,2,3,1 / 1,1,2,3 / 3,1,1,2]. Notice each row is the same set {2,3,1,1} but shifted one position right. In GF(2⁸), multiply by 2 = xtime operation (left shift + conditional XOR with 0x1B). For an exam: write the matrix, state it operates in GF(2⁸), and say "each output byte depends on all 4 input bytes of the column."

4. AddRoundKey — XOR with Round Key

AddRoundKey XORs the 128-bit State with the 128-bit round key for that round. The round key is derived from the original key using the key expansion algorithm. This is where the key enters the transformation — without the correct key, the other three transformations cannot be reversed properly.

AddRoundKey is the simplest transformation — just XOR the state with the round key byte by byte. But it's critical: this is the ONLY step where the actual key influences the encryption. Without the correct key, an attacker cannot undo the other transformations even if they know SubBytes, ShiftRows, and MixColumns algorithms.
AddRoundKey
State'[r][c] = State[r][c] ⊕ RoundKey[r][c] for each byte position
Equivalently: State' = State ⊕ RoundKey[round]
AddRoundKey is its own inverse: applying it twice restores the original (XOR is self-inverse)
Used at round 0 (before any round), and at the end of each round 1..N

Why Key Expansion?

AES needs 11 round keys (for AES-128) — one for the initial AddRoundKey and one for each of the 10 rounds. Each round key is 128 bits (16 bytes). The original key is only 128 bits. The Key Expansion algorithm expands 128 bits into 11×128 = 1408 bits of round key material.

You have one master key (128 bits = 16 bytes). But AES needs 11 round keys. The key expansion algorithm is like a copy machine that uses your master key to generate 11 different but mathematically related sub-keys. Any change in the master key completely changes all 11 sub-keys.
Key Expansion — Data Structure
W[i] = 32-bit word (4 bytes)
For AES-128: 44 words W[0..43] generated from 4 words W[0..3] (the original key)
Round key for round r = W[4r], W[4r+1], W[4r+2], W[4r+3]
Original 16-byte key → W[0]‖W[1]‖W[2]‖W[3] (four 32-bit words)

Key Expansion — The Algorithm ⭐⭐⭐

1
Initialise: The first 4 words W[0..3] are directly from the original 128-bit key. W[0] = first 4 bytes of key, W[1] = next 4 bytes, etc.
2
For i = 4 to 43 (for AES-128):
If i is NOT a multiple of 4 → W[i] = W[i-1] ⊕ W[i-4] (simple XOR with previous word and word 4 back)
If i IS a multiple of 4 → W[i] = W[i-4] ⊕ SubWord(RotWord(W[i-1])) ⊕ Rcon[i/4]
Three Helper Operations Used in Key Expansion
RotWord(a₀a₁a₂a₃): Rotate word left by 1 byte → returns (a₁a₂a₃a₀)
Example: RotWord(09CF4F3C) = CF4F3C09
SubWord(a₀a₁a₂a₃): Apply AES S-box to each of the 4 bytes individually
Example: SubWord(CF4F3C09) → apply S-box to each byte separately
Rcon[i]: Round constant for round i = (RC[i], 00, 00, 00)
RC[1]=01, RC[2]=02, RC[3]=04, RC[4]=08, RC[5]=10, RC[6]=20, RC[7]=40...
Each RC[i] = 2×RC[i-1] in GF(2⁸) (multiply by x in GF(2⁸))
Rcon values in hex: 01,02,04,08,10,20,40,80,1B,36 for rounds 1–10

Why Modes of Operation?

A block cipher like AES encrypts exactly 128 bits at a time. Real messages are rarely exactly 128 bits — they can be megabytes long. Modes of operation define how to apply a block cipher repeatedly to encrypt messages of arbitrary length, while also adding properties like IV (Initialization Vector) and feedback to prevent identical blocks from producing identical ciphertext.

Modes of operation answer: "How do we use a cipher that works on 16-byte chunks to encrypt a 1MB file?" Different modes have different trade-offs — some are simple (ECB) but weak, others add chaining (CBC) for security, and some create stream-cipher-like behaviour (CTR, CFB, OFB) that can encrypt any length without padding.

1. ECB — Electronic Code Book Mode (Simplest, Weakest)

ECB Mode
Encryption: Cᵢ = E(K, Pᵢ) ← each block encrypted independently
Decryption: Pᵢ = D(K, Cᵢ) ← each block decrypted independently
CRITICAL WEAKNESS: Same plaintext block → same ciphertext block. Patterns in plaintext show up in ciphertext!
Famous example: ECB-encrypted bitmap image — the picture's shape remains visible (like the Linux penguin outline)
PropertyECB

Random access✅ Yes — decrypt any block without others
Error propagation✅ Isolated — one corrupt block = one corrupt block
Patterns revealed❌ YES — identical input blocks → identical output
IV needed❌ No — but this is a weakness
Use caseKey encryption, rarely for data (NOT recommended)
⚠️
ECB Weakness — Always Write in Exam

"The fundamental weakness of ECB is that identical plaintext blocks produce identical ciphertext blocks. An attacker can identify patterns without decrypting — for example, the ECB-encrypted Linux Tux penguin image still shows the shape of the penguin. ECB should NEVER be used for encrypting large data or data with repeated patterns."

2. CBC — Cipher Block Chaining Mode (Most Used, Recommended)

CBC fixes ECB's weakness by XOR-ing each plaintext block with the previous ciphertext block before encryption. This means identical plaintext blocks produce different ciphertext blocks (because the previous ciphertext is different each time).

CBC Mode — Formulas
Encryption: Cᵢ = E(K, Pᵢ ⊕ Cᵢ₋₁) C₀ = IV (Initialization Vector)
Decryption: Pᵢ = D(K, Cᵢ) ⊕ Cᵢ₋₁ C₀ = IV (must be same as encryption)
IV: Random, publicly shared, different for each message — prevents two identical messages from having identical ciphertext

3. CFB — Cipher Feedback Mode (Stream-like)

CFB turns a block cipher into a self-synchronising stream cipher. Instead of encrypting the plaintext directly, it encrypts the previous ciphertext block and XORs the result with the plaintext.

CFB Mode — Formulas
Encryption: Cᵢ = Pᵢ ⊕ E(K, Cᵢ₋₁) C₀ = IV
Decryption: Pᵢ = Cᵢ ⊕ E(K, Cᵢ₋₁) (Note: ENCRYPT on decryption side too!)
Key difference from CBC: In CFB, the block cipher E(K) encrypts the CIPHERTEXT (not plaintext) to generate a keystream
Advantage: Can encrypt less than a full block (stream behaviour). No padding needed. Self-synchronising.
💡
CFB vs CBC — Key Difference for Exam

CBC: encrypt the XOR of plaintext and previous ciphertext → C = E(K, P⊕C_prev)
CFB: encrypt the previous ciphertext, then XOR with plaintext → C = P ⊕ E(K, C_prev)
In CBC, E(K) takes plaintext-XOR as input. In CFB, E(K) takes ciphertext as input. Both use same IV as C₀. CFB's decryption also uses E (not D), making it simpler to implement if only the encryption primitive is available.

4. OFB — Output Feedback Mode (Fully Parallel Keystream)

OFB generates a keystream independently of the plaintext and ciphertext by repeatedly encrypting the IV. This makes OFB a synchronous stream cipher — the keystream can be pre-computed before the message arrives.

OFB Mode — Formulas
Keystream: Oᵢ = E(K, Oᵢ₋₁) O₀ = IV
Encryption: Cᵢ = Pᵢ ⊕ Oᵢ
Decryption: Pᵢ = Cᵢ ⊕ Oᵢ
Oᵢ = keystream independent of plaintext/ciphertext — can be pre-computed!
Error in Cᵢ only corrupts Pᵢ (no error propagation) — good for noisy channels
Disadvantage: If keystream Oᵢ is known, attacker can flip specific plaintext bits by flipping corresponding ciphertext bits (bit flipping attack)

5. CTR — Counter Mode (Modern Favourite)

CTR mode encrypts successive counter values (counter = IV + i) to generate a keystream, then XORs with plaintext. This allows fully parallel encryption/decryption and random access to any block.

CTR Mode — Formulas
Counter: Tᵢ = IV ‖ i (IV concatenated with block counter i)
Encryption: Cᵢ = Pᵢ ⊕ E(K, Tᵢ)
Decryption: Pᵢ = Cᵢ ⊕ E(K, Tᵢ) (same formula!)
Advantages: Fully parallel (all Tᵢ values independent) | Random access | No padding needed | Pre-computable keystream
Used in: AES-CTR for TLS 1.3, IPSec, WPA2 wireless security

Q. Explain the Electronic Code Book (ECB) and Cipher Block Chaining (CBC) modes of block cipher operations.
2024 Part C Q2 · 10 marks ⭐⭐⭐ECB + CBC🔮 VERY HIGH 2026
ECB — Electronic Code Book Mode:

ECB is the simplest block cipher mode. Each plaintext block is encrypted independently with the same key.

Encryption: Cᵢ = E(K, Pᵢ)
Decryption: Pᵢ = D(K, Cᵢ)

Advantages: Simple | Parallel encryption/decryption | Random access to any block
Disadvantages: FATAL FLAW — identical plaintext blocks produce identical ciphertext. Statistical patterns in plaintext are preserved in ciphertext. An attacker can identify which blocks are identical without decryption.
Example of weakness: ECB-encrypted penguin image — the shape of the penguin remains visible!
Use: Key encryption — when all blocks are different (not for bulk data)

[Draw: P₁→E(K)→C₁, P₂→E(K)→C₂, P₃→E(K)→C₃ — all independent, same key]

CBC — Cipher Block Chaining Mode:

CBC fixes ECB's pattern problem by XOR-ing each plaintext block with the PREVIOUS ciphertext block before encryption. This chains the blocks together — any change early in the message affects all subsequent ciphertext.

Encryption: Cᵢ = E(K, Pᵢ ⊕ Cᵢ₋₁) where C₀ = IV (Initialization Vector)
Decryption: Pᵢ = D(K, Cᵢ) ⊕ Cᵢ₋₁ where C₀ = IV

IV: A random 128-bit value, different for each message. Prevents identical messages from having identical ciphertext. IV is publicly shared (not secret).

Advantages: Identical blocks → different ciphertext (no pattern leakage) | Standard for most encryption uses | Decryption can be parallelised
Disadvantages: Encryption must be sequential (needs previous ciphertext) | Error in Cᵢ corrupts Pᵢ AND Pᵢ₊₁ (two-block error propagation)
Use: File encryption, disk encryption, TLS record encryption, database encryption

Q. Explain block cipher modes of operations with suitable diagrams.
2023-Jul Part C Q2 · 10 marks ⭐⭐⭐All Modes🔮 HIGH 2026
Introduction: A block cipher processes one fixed-size block at a time. Modes of operation define how to apply a block cipher repeatedly for messages of arbitrary length.

Five Modes:

1. ECB: Cᵢ = E(K, Pᵢ) | Simplest | Identical blocks → identical ciphertext (weakness) | Parallel

2. CBC: Cᵢ = E(K, Pᵢ⊕Cᵢ₋₁), C₀=IV | Chained | No patterns | Sequential encryption | Most used

3. CFB: Cᵢ = Pᵢ⊕E(K,Cᵢ₋₁), C₀=IV | Stream-like | Decryption uses E (not D) | Can encrypt <128 bits

4. OFB: Oᵢ=E(K,Oᵢ₋₁); Cᵢ=Pᵢ⊕Oᵢ | Keystream pre-computable | No error propagation | Good for noisy channels

5. CTR: Cᵢ=Pᵢ⊕E(K,IV+i) | Fully parallel | Random access | Modern standard (TLS 1.3)

Q. Explain the Electronic Code Book (ECB) block cipher mode of operation.
2025 Part B Q6 · 4 marks ⭐⭐ECB Mode
ECB — Electronic Code Book Mode:

ECB is the simplest and most naive mode of operation. The plaintext is divided into b-bit blocks. Each block is encrypted independently using the same key K.

Formulas:
Encryption: Cᵢ = E(K, Pᵢ) for i = 1, 2, ..., N
Decryption: Pᵢ = D(K, Cᵢ) for i = 1, 2, ..., N

[Draw: Three parallel encryption paths P₁→E(K)→C₁, P₂→E(K)→C₂, P₃→E(K)→C₃]

Advantages:
• Simplest to implement — no chaining or IV required
• Fully parallel — all blocks can be encrypted/decrypted simultaneously
• Random access — any block can be decrypted independently
• Error isolation — corruption in Cᵢ only affects Pᵢ, not other blocks

Disadvantages (Critical!):
• PATTERN LEAKAGE: Same plaintext block always produces same ciphertext. Structural patterns in plaintext are visible in ciphertext.
• NOT suitable for encrypting structured data with repeated blocks (e.g., images, database records)
• Susceptible to replay attacks — attacker can rearrange ciphertext blocks

Example weakness: ECB-encrypted bitmap of a penguin still shows the outline of the penguin in the ciphertext.

Usage: ECB is only safe when all blocks are guaranteed to be unique (e.g., encrypting a single session key). Never use for bulk data.
Q. In SSL and TLS, why is there a separate change cipher spec protocol rather than including a change-cipher-spec message in the handshake protocol?
2023-24 (61N0403) Part B Q6 · 4 marks ⭐SSL/TLS Cipher Modes
The separate ChangeCipherSpec (CCS) protocol in SSL/TLS exists for the following reasons:

1. Clear protocol demarcation: The handshake and record protocols serve different functions. CCS signals the exact moment when the negotiated cipher suite takes effect — creating a clean boundary between "old" (pre-handshake, no encryption) and "new" (post-handshake, encrypted) modes. Including it in the handshake would blur this boundary.

2. Sequencing guarantee: CCS is processed in the order it arrives in the record stream. Separating it from the handshake messages ensures proper sequencing — the switch to new cipher parameters happens only AFTER all handshake messages have been processed and verified.

3. Simplicity of handshake parser: The handshake protocol parser only handles key exchange and authentication messages. CCS is just a 1-byte message (value 0x01) — too simple to deserve a handshake message type, but important enough to need its own protocol layer.

4. Historical design (SSL 3.0): The SSL 3.0 designers separated it to keep the state machine clear — handshake negotiates parameters; CCS activates them; record protocol uses them. Three distinct phases, three distinct protocols.
